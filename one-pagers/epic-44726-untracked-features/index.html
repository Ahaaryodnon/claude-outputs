Why this matters: anything built without a story is invisible to planning, QA scope, and the acceptance-criteria validation that just completed (46298). It will not be tested, estimated, or documented unless it is put on the board. The workforce-recording feature followed exactly this path — built untracked, then raised retrospectively as 46198 — and these are the remaining candidates. The iOS companion app that a previous cycle flagged as the largest gap is not present in the tree on the current branch (Dev), so it stays off this list — its Maestro flows do still sit on the Testing branch. The Android tree has not changed since 30 July, so the seven untracked capabilities below stand unchanged, and none of them gained a story. The board was read live again this refresh after two refreshes without it, and one thing on it has moved towards this list: a new story, the end-to-end photo flow test plan (49764), is the first board item to name the capture-annotate-queue-upload chain that the second table below has flagged as untested. It sits in refinement and has produced no test yet, so the gap is acknowledged rather than closed. Three further stories were added under Route to production, and none covers a capability on this list. The five core field-app stories that reached Ready to Deploy are still sitting in that band across a third reading, which keeps the stake on this list high, because anything shipped from there carries these untracked capabilities with it, unstoried and unscoped for QA. The ten detached field-app defects are still detached, and the four that stayed in the epic have all fallen back to Blocked. The hosted map-tile source has now left the board entirely rather than being resolved on it: 49066 was already removed and 49067 has followed it out of the backlog, so neither half of the tile pair is tracked any more.
