Data currency, refresh of 28 August 2026. The board has been read live again. Every work item state, owner and count on this page was pulled from Azure DevOps this morning, which ends the two-refresh blackout the last two dashboards carried and closes the gap that had been widening behind them. Because the previous reading was 25 August, the movement described below spans that whole gap rather than a single cycle, and it is written as movement since the board was last read. Row notes that were written before the blackout and still say "this cycle" refer to the 25 August reading, not to today. The coverage figures are current in the same way: the Android repository was re-inventoried today and the unit suite was re-run from a forced re-run and passed. Board data and test data are now both live.

The epic was restructured in early June: automated testing was promoted to its own feature, a Future Scope feature now holds deferred work, and a Route to Production feature gathers the deployment work — its original pipeline story (45960) is now Done under the Platform team, and it has grown into a full Azure deployment breakdown covering Key Vault and secrets, a DbUp migration runner, Azure Files image storage, App Service hardening, observability, auth, and CI/CD — those deployment stories have each been decomposed into delivery tasks, around sixty in total, from ingress and secret-delivery decisions through to slot-swap promotion. Route to Production also carries a Platform-team workstream — the API repository set-up, access and permissions, App Service Terraform, Azure File Sync, an on-prem sync agent, a .NET 9 build pipeline, the deployment pipeline, and connectivity and security. Under the field-app feature, production-parity stubs mirror the RP sign-off, mapping, offline mapping, workforce, and in-app audit work alongside the login and work-order stubs, and scope stories cover feature flags to hide non-MVP surfaces, photo limits and image size, a photo gallery, job-versus-man hours, and sign-off questions.

Reading the board again after three days shows a wider set of moves than a single cycle would. Twelve items changed state, three changed hands and four were added, so the board shown here goes from 112 items to 116. The moves split cleanly in two directions: the route to production finished its work, while the field-app defect wave went backwards.

The route to production has finished its pipeline. The CI/CD pipeline story (47039) — which the dashboard of 25 August singled out as the one part of the route that had not moved while the app in front of it became deploy-ready — has gone from Blocked to Done in two readings, and the one-pipeline spike that fed it (49407) closed alongside it under the same owner, Keerthi Jagarlamudi. Its eight delivery tasks are all still at New, so the story is recorded as Done ahead of the task breakdown beneath it, which is worth a check before anyone treats the pipeline as complete. Four items were added under the same feature: a Platform-team blob storage change (49708), which is already Done; an Azure Arc managed identity for the on-prem file sync service (49762); a deployment pipeline for that service (49763), taken straight into development; and an end-to-end photo flow test plan (49764) in refinement.

The defect picture went the other way, and it is the clearest warning on this refresh. All four attachment-visibility defects that had just been taken into development with Aaron Haydon — permission documents (49195), survey pictures (49199), linked maps (49237) and electrical and ecological risk (49388) — have fallen back to Blocked as a group. They were the four that stayed inside the epic when the rest of the field-trial wave was detached, so the epic-level defect picture now shows every retained field defect stalled rather than progressing. The Woodplan RP sheet creation logic (45962) also fell back to Blocked, giving up the Awaiting QA position it had only just reached. Blocked has gone from two items to seven, and it is the only band on this page that grew.

Six items were taken off the backlog outright, which is where much of the apparent forward movement comes from. The on-prem API route was closed out as a pair — the API implementation (46887), previously the longest-running item in QA, and the on-prem image storage structure (46886), previously the one remaining blocked item — so the on-prem deployment route is no longer a tracked deliverable and the Azure route carries the deployment alone. Connectivity, security and access (47229) was removed from refinement. The hosted map-tile source was removed in full: 49066 had already gone and 49067 has now followed it, so both halves of the tile pair have left the board while the Android side keeps a built and unit-tested PMTiles archive and tile-server stack with no tracked source to point at. Removals are not completions, and six of them in one reading flatter the trend if they are read as progress.

The structural gap reported last time is confirmed rather than closed. Ten of the field-app defects raised across the earlier cycles still sit outside Epic 44726 with no parent at all — site-specific risk assessment (49196), client method statement (49197), shutdown work orders (49256), RP sheet status after sync (49362), revisit date mismatch (49363), work order status after completion (49364), off-site date-time recording (49387), the SSE Excel macro (49389), date-time and location on actions (49405), and the login field-mapping defect (49104) that was already detached last cycle. Each was re-read from the board this morning and none has changed state since. They are kept on this dashboard for continuity, but they are still counted nowhere on the epic. The four defects from the same wave that stayed in the epic are the four that have now blocked together (49195, 49199, 49237, 49388), so neither half of the field-trial backlog is moving. Anyone reading epic-level defect counts should know that the majority of the field-trial backlog is now invisible to them.

Coverage is reported from the current working branch, Dev, exactly as it stands in the tree, and it has been run rather than only counted for the fourth refresh running. The branch carries 111 JVM unit tests across 23 files, and this refresh executed them again from a forced re-run rather than a cached result: gradlew testDebugUnitTest --rerun-tasks completed with BUILD SUCCESSFUL in 50 seconds, 33 tasks executed, and the JUnit results were rewritten this morning recording 111 tests, zero failures, zero errors and zero skipped across 23 result files. Two practical notes for anyone reproducing it. The checkout has no local.properties, so the build cannot find the SDK on its own and the run needs ANDROID_HOME pointing at the Android SDK; with that set, build-tools 36.0.0 alongside 36.1.0 and 37.0.0 let the suite compile and run end to end. The gradlew wrapper in this checkout also has no executable bit, so it has to be invoked as sh gradlew rather than ./gradlew; a first attempt this morning failed on that alone and would have been read as a passing run if the result timestamps had not been checked. Every unit chip on this page is therefore verified green as of this refresh rather than merely present. The suites cover completion question, audit, dictation, operational-info and photo-limit rules, the map feature mappers, UI-state reducers, camera-safety and location-fix logic and offline state, the offline map pack, PMTiles archive and tile-server stack, the on-prem API client configuration, sync-summary and session-token logic, the app-update URL validator, debug-build guards, time utilities, the financial-password verifier, and an annotation-editor saved-state audit. Two instrumented test files, the Room database migration test and the sample instrumented test, sit alongside them and were not run, as they need a device or emulator.
