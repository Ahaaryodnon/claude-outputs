The epic was restructured in early June: automated testing was promoted to its own feature, a Future Scope feature now holds deferred work, and a Route to Production feature gathers the deployment work — its original pipeline story (45960) is now Done under the Platform team, and it has grown into a full Azure deployment breakdown covering Key Vault and secrets, a DbUp migration runner, Azure Files image storage, App Service hardening, observability, auth, and CI/CD — those deployment stories have each been decomposed into delivery tasks, around sixty in total, from ingress and secret-delivery decisions through to slot-swap promotion. Route to Production also carries a Platform-team workstream — the API repository set-up, access and permissions, App Service Terraform, Azure File Sync, an on-prem sync agent, a .NET 9 build pipeline, the deployment pipeline, and connectivity and security. Under the field-app feature, production-parity stubs mirror the RP sign-off, mapping, offline mapping, workforce, and in-app audit work alongside the login and work-order stubs, and scope stories cover feature flags to hide non-MVP surfaces, photo limits and image size, a photo gallery, job-versus-man hours, and sign-off questions.

Coverage is reported from the current working branch, Dev, exactly as it stands in the tree, and it has been run rather than only counted for the eighth refresh running. The branch carries 111 JVM unit tests across 23 files, and this refresh executed them again from a forced re-run rather than a cached result: gradlew testDebugUnitTest --rerun-tasks completed with BUILD SUCCESSFUL in 48 seconds, 33 actionable tasks all executed, and the JUnit results were rewritten at 08:09 this morning recording 111 tests, zero failures, zero errors and zero skipped across 23 result files. The forced re-run is used, and the result timestamps checked, because a plain invocation returns UP-TO-DATE without running anything; no chip on this page is called green on a cached result. Two practical notes for anyone reproducing it. The checkout has no local.properties, so the build cannot find the SDK on its own and the run needs ANDROID_HOME pointing at the Android SDK. The gradlew wrapper in this checkout also has no executable bit, so it has to be invoked as sh gradlew rather than ./gradlew. Every unit chip on this page is therefore verified green as of this refresh rather than merely present. The suites cover completion question, audit, dictation, operational-info and photo-limit rules, the map feature mappers, UI-state reducers, camera-safety and location-fix logic and offline state, the offline map pack, PMTiles archive and tile-server stack, the on-prem API client configuration, sync-summary and session-token logic, the app-update URL validator, debug-build guards, time utilities, the financial-password verifier, and an annotation-editor saved-state audit. Two instrumented test files, the Room database migration test and the sample instrumented test, sit alongside them and were not run, as they need a device or emulator.
