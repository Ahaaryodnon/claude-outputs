The Azure DevOps connection was unavailable on this run, as it was on the run before it, so every work item state, owner and count on this page is still carried forward unchanged from the refresh of 25 August 2026 and has now gone two refreshes without being re-read from the board. The cycle narrative below therefore describes the moves recorded at that refresh, not new movement, and the distance between it and the live board is widening rather than holding. The coverage figures are current: the Android repository was re-inventoried today and the unit suite was re-run and passed. Treat the board data as two refreshes old and the test data as live.

The epic was restructured in early June: automated testing was promoted to its own feature, a Future Scope feature now holds deferred work, and a Route to Production feature gathers the deployment work — its original pipeline story (45960) is now Done under the Platform team, and it has grown into a full Azure deployment breakdown covering Key Vault and secrets, a DbUp migration runner, Azure Files image storage, App Service hardening, observability, auth, and CI/CD — those deployment stories have each been decomposed into delivery tasks, around sixty in total, from ingress and secret-delivery decisions through to slot-swap promotion. Route to Production also carries a Platform-team workstream — the API repository set-up, access and permissions, App Service Terraform, Azure File Sync, an on-prem sync agent, a .NET 9 build pipeline, the deployment pipeline, and connectivity and security. Under the field-app feature, production-parity stubs mirror the RP sign-off, mapping, offline mapping, workforce, and in-app audit work alongside the login and work-order stubs, and scope stories cover feature flags to hide non-MVP surfaces, photo limits and image size, a photo gallery, job-versus-man hours, and sign-off questions.

This cycle was the mirror of the last one. Where the previous cycle moved the field app forward and left the route to production standing still, this one barely touched the field app and moved the route to production decisively. One item was added — the published-work file copier (49542) under Route to production — so the board shown here goes from 111 items to 112. Nine items changed state and two changed hands, and eight of those nine moves were forwards.

Auth and security hardening (47038) closed to Done with its rate-limiting, BCrypt, security-header and token-lifetime tasks all Closed, and both open spikes in this area closed as well — durable image and file storage on Azure Files (47035) and the information_centre database assessment (48939). The one-pipeline spike (49407) was taken up into Active and reassigned from Ross Bishop to Keerthi Jagarlamudi, so it now sits with the pipeline story under the same owner. Blocked is down to a single in-epic item, the on-prem image storage structure (46886).

Coverage is reported from the current working branch, Dev, exactly as it stands in the tree, and it has been run rather than only counted for the third refresh running. The branch carries 111 JVM unit tests across 23 files, and this refresh executed them again from a forced re-run rather than a cached result: gradlew testDebugUnitTest --rerun-tasks completed with BUILD SUCCESSFUL in 59 seconds, 33 tasks executed, and the JUnit results were rewritten this morning recording 111 tests, zero failures, zero errors and zero skipped across 23 result files. One practical note for anyone reproducing it: the checkout has no local.properties, so the build cannot find the SDK on its own and the run needs ANDROID_HOME pointing at the Android SDK; with that set, build-tools 36.0.0 alongside 36.1.0 and 37.0.0 let the suite compile and run end to end. Every unit chip on this page is therefore verified green as of this refresh rather than merely present. The suites cover completion question, audit, dictation, operational-info and photo-limit rules, the map feature mappers, UI-state reducers, camera-safety and location-fix logic and offline state, the offline map pack, PMTiles archive and tile-server stack, the on-prem API client configuration, sync-summary and session-token logic, the app-update URL validator, debug-build guards, time utilities, the financial-password verifier, and an annotation-editor saved-state audit. Two instrumented test files, the Room database migration test and the sample instrumented test, sit alongside them and were not run, as they need a device or emulator.
